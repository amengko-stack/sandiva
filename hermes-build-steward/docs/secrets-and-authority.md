# Secrets, credentials, and authority

No secret value belongs in source, Build Tasks, prompts, logs, results, synced folders, or this inventory.

| Logical name | Purpose | Required scope | Storage type/location | Rotation | Revocation |
|---|---|---|---|---|---|
| `HermesGraphCertificate` | Obtain short-lived Microsoft Graph app-only tokens on the Hostinger VM | Read only approved Control Tower specification/acceptance artifacts; read/write only the dedicated Hermes runtime-state list | External PFX file, recommended under `/etc/sandiva-hermes/credentials/`, owned and readable only by the `sandiva-hermes` service account | Upload the replacement public certificate to the Entra application, install its private-key PFX with restrictive ownership/mode, switch the configured path, then remove the old certificate | Remove the certificate from the Entra application, revoke the resource-specific grants, and remove the VM credential file |
| `HermesAzureManagedIdentity` | Optional Graph authentication only when running independently on an authorized Azure VM | Same selected-resource boundary; never broader merely because the adapter differs | Azure VM system-assigned or approved user-assigned managed identity; no secret file | Replace/rebind the managed identity and re-grant the narrow resource permissions | Remove the selected permission grant or disable/delete the managed identity |
| `HermesGitHubReadIdentity` | Read designated private repository commit/PR/check evidence if anonymous read is unavailable | Read-only metadata/checks for explicitly designated repositories | Approved GitHub App/workload token broker on the VM; not implemented or provisioned by this build | Rotate in the GitHub App/token broker | Revoke installation or repository grant |
| `VerificationImageDigest` | Pin the approved untrusted-job runtime image | Pull/use one approved image only | Non-secret VM runtime configuration | Approve and deploy a new digest | Remove the digest/image from the VM allowlist/cache |

The Hostinger production path uses MSAL confidential-client certificate authentication and requests only `https://graph.microsoft.com/.default`. MSAL receives the PFX path directly; this implementation does not read the private key into task, audit, result, or job data and does not implement a client-secret fallback. Tokens and the bounded token cache remain in coordinator process memory and are never logged or passed to the container job. Azure managed identity remains an optional independent adapter, but Hostinger production configuration rejects it. A GitHub token provider is injectable for a private repository, but this build neither stores nor provisions one.

The intended Microsoft 365 permission model uses resource-specific selected application permissions and explicit resource grants: read only for the approved Control Tower evidence location, and read/write only for the dedicated Hermes runtime-state list. Prefer the narrowest technically available selected scope, including file/folder selection for named evidence or list selection for the approved document library, plus `Lists.SelectedOperations.Selected` for the runtime list. The runtime application must not receive permission-management roles or broad tenant-wide Graph write permission. If tenant policy or the selected-permission model cannot narrow these grants sufficiently, return `PARTNER DECISION REQUIRED` before granting broader access.

Phase 1 explicitly denies merge, deployment, production-code mutation, specification mutation, Partner Decision resolution, production client-document access, Codex dispatch, and Claude Code dispatch. The container gets none of the trusted coordinator authorities.
